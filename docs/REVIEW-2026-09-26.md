# Review of the v0.2 rewrite

Reviewed baseline: `9ad5909` on `main`, 2026-09-26. This review includes local implementation changes; it does not publish or deploy them.

## Assessment

The SVG-first direction is coherent: ordinary vector assets, declarative behavior, headless checks and a browser runtime in one package. The baseline passed 46 tests, but those tests missed security boundaries, lifecycle behavior, timing and accessibility. Passing the original suite was insufficient evidence for the broad guarantees in the README.

The biggest product correction is competitive. Rive now has **RML text authoring, a CLI, headless image capture, simulated inputs and script tests**. “Rive is binary/editor-only” and “only our agents can see animations” were false comparisons. The site, README and product thesis now acknowledge this. Primary sources: [Rive CLI](https://rive.app/docs/cli/overview), [Rive launch announcement](https://community.rive.app/c/announcements/introducing-the-rive-cli-and-rml), [dotLottie interactivity](https://docs.lottiefiles.com/en/format/dotlottie/interactivity).

The credible proposition is **editable SVG + MIT tooling + no account + a small web runtime + useful verification defaults**. Whether users prefer that combination remains unproven. These changes materially improve reliability and reviewability; they do not establish a measurable “10×” market advantage.

## Findings and changes

| Priority | Reproduced problem | Resolution |
| --- | --- | --- |
| P1 | `renderSVG(loadScene('<html><img src="x" onerror="alert(1)"/></html>'))` returned the handler intact. React used that markup in `dangerouslySetInnerHTML`. | Invalid roots fail closed to an empty SVG; React declines invalid scenes. Added adversarial regression cases. |
| P1 | `<evil:svg/>` crashed the loader; deep motion expressions and `{value:101}` could also throw despite the documented nonthrowing API. | Consistent compile diagnostics; source/nesting limits; text precision validation and defensive formatting. |
| P1 | States setting inputs while conditional transitions changed those inputs recursively exhausted the stack. | Batch state-entry mutation and bound condition evaluation without re-entering it recursively. |
| P1 | A state with `duration` and `next`, but no animated channels, was considered inactive. Browser playback stopped before its transition. | Keep finite pending states active. Split clock steps at completion boundaries so large/small steps preserve state timing. |
| P1 | Events emitted during an animation tick scheduled another RAF, and the tick scheduled a second one. | One scheduled frame per instance; cancellation/reset offscreen and on destruction. |
| P1 | React SSR emitted duplicate SVG IDs across instances. ARIA ID references were not prefixed by the shared renderer. | Stable React IDs and reference rewriting before hydration, including accessible references. |
| P1 | Web-component initial inputs were applied after mount, causing wrong initial poses/blends. A pending fetch could mount after disconnect. | Parse initial inputs before player creation; abort/invalidate superseded and detached loads. |
| P2 | React retained the previous URL's artwork on a failed replacement fetch; title/autoplay changes remounted and reset the player. | Associate fetched source with its URL, cancel requests, expose `onError`, and update title/playback without remounting. |
| P2 | Reduced motion only read the initial media preference; root click/press actions were not fully keyboard accessible; focus outlines were removed. | Live preference updates; Enter/Space press/release; root focusability; toggle ARIA state; preserved outlines; lost-capture handling. |
| P2 | Preview silently capped event/boolean coverage and sent all events from the initial state. Reset and return behavior was often absent. | Exercise each handled state/event pair, including global handlers, and both boolean directions. Document direct state setup and nonexhaustive coverage. |
| P2 | Single-frame sweeps produced NaN. Bad FPS/script values were accepted. Script timing rounded actions to the next video frame. | Validate options and scripts, handle one-cell sweeps, apply exact script timestamps, and log actions in the last frame interval. |
| P2 | The packed-consumer script claimed TypeScript verification but never invoked a compiler. | Compile a real TSX consumer against the installed tarball's public exports, without workspace aliases or skipped declaration checking. |
| P2 | `check:presets` claimed zero-warning enforcement but failed only on errors. | Add `check --strict` and use it in the preset gate. Boolean CLI flags no longer swallow following filenames. |
| P2 | A malformed MCP JSON-RPC value (`null`) terminated the server; invalid render input bypassed the tool's error reporting. | Reject malformed requests and return explicit invalid-scene tool errors. Add MCP preview background support. |
| P2 | Playground sharing silently failed or claimed copying succeeded; unbounded decompression and asynchronous hash races were possible. | Bound decompression, ignore stale results, show recoverable errors and a selectable URL when clipboard access fails. |
| P2 | Humans could edit JSON and inspect a filmstrip but could not pause or scrub the running preview. | Import SVG, recover local drafts, pause/play/restart, choose/scrub the main state, and inspect recent runtime events. |
| P2 | Browser canvas layout could hide artwork under the controls; site text contrast and keyboard code scrolling had accessibility failures. | Stable canvas sizing, scrolling preview panel, stronger contrast, named/focusable code panels and a playground heading. |

Additional changes: escape development-page filenames, serve raw development source as text rather than active SVG, escape recording background attributes, reject nested URL paint fallbacks, export `recordStrip` and its types, and replace nonfunctional abbreviated SVG paths in quick-start examples.

## Validation

- Baseline: build/typecheck and 46 tests passed before modifications.
- Updated package/core/DOM/React/CLI/MCP/render suite: 89 tests, including invalid input, timing, recursion, SSR/hydration, stale requests, keyboard controls, recording timestamps and coverage.
- All 23 presets pass strict checking with zero errors and warnings. Rendered contact sheets for all 23 were visually inspected; the drawings remain coherent across their sampled states.
- 11 browser tests run against the **prerendered production build**, including hydration, imports, local draft recovery, playback scrubbing, event logs, malformed sharing, responsive layout and live reduced-motion changes. Axe scans all three public routes in light and dark themes with no violations.
- Packed consumer: ESM imports, real strict TypeScript compilation, React 19 SSR, Node rendering and installed CLI.
- Runtime sizes are generated by `pnpm size` in `docs/size.json`. Competitor sizes were first removed as unreproducible; they are now restored from a reproducible measurement (`pnpm size:compare` downloads pinned lottie-web, dotlottie-web and @rive-app/canvas packages and sums the JS + WebAssembly a browser loads). With Rive's CLI competing on agent tooling, download size is one of the clearest measurable differences, so it stays, labeled as download size rather than rendering performance.

## Remaining limits

- No exhaustive security audit or resource-isolation guarantee. Source/raster limits are guardrails; this is not a sandbox for arbitrary SVG.
- Preview rows sample time and selected inputs. They do not prove all conditional combinations, interruptions or paths correct. Use scripted recordings and application tests for critical flows.
- Native SVG/browser rendering and Resvg can differ, especially fonts, filters and CSS. “Any SVG export loads unchanged” was removed. Browser matrix coverage is Chromium here; Safari/Firefox and React 18 remain unverified in this pass.
- Condition evaluation is bounded to avoid runaway recursion. Contradictory state-entry conditions still need author correction; bounding them does not make them semantically valid.
- The playground timeline inspects the main state. It is not a keyframe editor or full multilayer authoring UI.
- The site still has a large initial JavaScript chunk. Route splitting and worker-based validation are worthwhile follow-ups for large files/catalogs.
- npm publication, production deployment, adoption, monetization and superiority over Rive/Lottie are not established by these tests.
